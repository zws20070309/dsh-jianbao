# 版式规范（实测自参考 PDF）

**唯一权威样本**
`远端仓库参考内容/简报/2026下/西藏大学理学院信息〔2026〕74号 西藏大学理学院召开2026级新生见面会暨入学教育动员大会(1).pdf`
（Word for Microsoft 365 导出，494286 字节，4 页）

下面每个数字都是从这份 PDF 的 **span 级 origin（基线）与 bbox** 反推出来的。
复核命令：

    python _tmp/dump_baseline.py          # 逐行基线
    node tools/geometry-diff.mjs ours.pdf ref.pdf --tol 0.5

单位一律 **bp**（PostScript big point，1bp = 1/72in = PDF 的用户单位）。

> 为什么不用 TeX 的 `pt`：1pt = 1/72.27in。写 `\fontsize{16pt}{28.8pt}`，XeTeX 实际
> 渲染出 15.94bp / 28.69bp，与 Word 的 15.96 / 28.80 每行差 0.11 —— 20 行漂 2.2bp。
> 改用 bp 后行距精确等于 28.80bp。

> 这里此前写的是「正文不缩进」，并拿 600dpi 光栅扫描与 Word COM 当证据 ——
> **那是错的**。错误的根源是把参考 74 号的 PDF 当成权威：那份 PDF 由 Word 导出时
> **自己丢了 docx 的缩进设置**（首行墨迹确实与报头同一条垂线），但 docx 本体写着
